Preview your release notes as a web page before you tag

Release notes usually get written in a hurry, right after the tag. A better habit is to look at what is actually going out first: every commit since the last tag, grouped into new features, fixes, speedups and docs, on one page you can send to a teammate and ask "anything missing?"

This post walks through a single Python file (standard library only) that does that. It reads git log <last-tag>..HEAD, groups commits by their conventional-commit prefix, writes notes.html, and then asks you before putting it on a public link with deed.page. Nothing leaves your machine until you type y.

What it does

  • Finds the last tag with git describe --tags --abbrev=0 and lists every non-merge commit since then.
  • Sorts feat:, fix:, perf: and docs: commits into sections, and puts everything else under "Other". Commit subjects are HTML-escaped, so a subject like handle <stdin> shows up as text instead of breaking the page.
  • Writes notes.html and stops to ask. Answer anything but y and nothing is uploaded.
  • On yes, uploads the page with one HTTP PUT. The first anonymous upload returns an owner token; the script saves it to ~/.config/deed-page/token with mode 600 and never prints it.
  • Remembers the slug, so running it again after more commits updates the same URL instead of making a new one.
  • --delete takes the page down.

The script

#!/usr/bin/env python3
"""Turn `git log <last-tag>..HEAD` into a release-notes web page, and publish
it to a public deed.page URL only after you type y.

  python3 release_notes_page.py            # build notes.html, ask before publishing
  python3 release_notes_page.py --delete   # take the page down again
"""
import html, json, os, pathlib, secrets, subprocess, sys, urllib.request

CONF = pathlib.Path.home() / ".config" / "deed-page"
API = "https://deed.page/v1/sites"
GROUPS = [("feat", "New"), ("fix", "Fixed"), ("perf", "Faster"), ("docs", "Docs")]

def git(*args):
    return subprocess.run(["git", *args], capture_output=True, text=True).stdout.strip()

def build():
    since = git("describe", "--tags", "--abbrev=0")
    rng = f"{since}..HEAD" if since else "HEAD"
    lines = git("log", rng, "--no-merges", "--pretty=%h\x1f%s").splitlines()
    buckets = {label: [] for _, label in GROUPS}; buckets["Other"] = []
    for line in lines:
        sha, subj = line.split("\x1f", 1)
        kind = subj.split(":", 1)[0].split("(", 1)[0].lower()
        label = dict(GROUPS).get(kind, "Other")
        text = subj.split(":", 1)[1].strip() if label != "Other" and ":" in subj else subj
        buckets[label].append(f"<li>{html.escape(text)} <code>{sha}</code></li>")
    repo = html.escape(pathlib.Path(git("rev-parse", "--show-toplevel")).name)
    title = f"{repo}: changes since {html.escape(since) if since else 'the first commit'}"
    body = "".join(f"<h2>{k}</h2><ul>{''.join(v)}</ul>" for k, v in buckets.items() if v)
    page = (f"<!doctype html><meta charset=utf-8><meta name=viewport content='width=device-width'>"
            f"<title>{title}</title><style>body{{font:16px/1.5 system-ui;max-width:42rem;margin:2rem auto;padding:0 1rem}}"
            f"code{{color:#666}}</style><h1>{title}</h1><p>{len(lines)} commits</p>{body}")
    pathlib.Path("notes.html").write_text(page)
    return len(lines), title

def request(method, url, data=None):
    req = urllib.request.Request(url, data=data, method=method)
    tok = os.environ.get("DEEDPAGE_TOKEN", "")
    if not tok and (CONF / "token").exists():
        tok = (CONF / "token").read_text().strip()
    if tok: req.add_header("Authorization", f"Bearer {tok}")
    if data: req.add_header("Content-Type", "text/html")
    with urllib.request.urlopen(req) as r:
        return r.status, r.read().decode() or "{}"

def main():
    slug_file = CONF / "release-notes-slug"
    if "--delete" in sys.argv:
        slug = slug_file.read_text().strip()
        print(request("DELETE", f"{API}/{slug}")[0], "deleted", slug); return
    n, title = build()
    print(f"Wrote notes.html: {title} ({n} commits). Open it and check it first.")
    if input("Publish notes.html to a public URL? Anyone with the link can read it. [y/N] ").strip() != "y":
        print("Not published."); return
    slug = slug_file.read_text().strip() if slug_file.exists() else f"notes-{secrets.token_hex(4)}"
    status, raw = request("PUT", f"{API}?slug={slug}", pathlib.Path("notes.html").read_bytes())
    resp = json.loads(raw)
    CONF.mkdir(parents=True, exist_ok=True); os.chmod(CONF, 0o700)
    slug_file.write_text(slug)
    if resp.get("token"):  # first anonymous publish returns an owner token: keep it, never print it
        (CONF / "token").write_text(resp["token"]); os.chmod(CONF / "token", 0o600)
    print(status, resp.get("url", f"https://{slug}.deed.page/"))

if __name__ == "__main__":
    main()

Running it

$ python3 release_notes_page.py
Wrote notes.html: demo: changes since v0.1.0 (5 commits). Open it and check it first.
Publish notes.html to a public URL? Anyone with the link can read it. [y/N] y
201 https://notes-xxxxxxxx.deed.page/

$ git commit -m "fix: second fix"
$ python3 release_notes_page.py      # same URL, now 6 commits
...
200 https://notes-xxxxxxxx.deed.page/

$ python3 release_notes_page.py --delete
200 deleted notes-xxxxxxxx

I ran exactly this against a throwaway repo: answering n uploaded nothing and created no config files, y returned 201 and the page was live, the second run returned 200 on the same URL with the new commit, and after --delete the URL returned 404.

Using it from a coding agent

If an agent is drafting your release notes, keep the same rule: let it build notes.html, show you the file and the address it is about to use, and only publish after you say yes. Keep the owner token in the config file or an environment variable (DEEDPAGE_TOKEN) rather than in the prompt. The deed-page-skill repo packages this ask-first flow for agents, and the full HTTP API is in the deed.page docs.

Notes

  • Anyone with the link can open the page, so don't publish notes for a private repo you can't share.
  • If your team doesn't use conventional commits, everything lands under "Other", which is still a useful list.
  • Want it on every release? Call it from your release script right before git tag, so the yes/no prompt becomes part of cutting a release.
